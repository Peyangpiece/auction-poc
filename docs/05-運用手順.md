# 運用の手順

入札サーバーを動かす人のための手順です。実物（Lightsail・OBS・IVS）での確認は済んでいないので、初回は本番の前に必ずリハーサルで通してください。

## 1. 開催の前日まで

| 確かめること | やり方 |
|---|---|
| サーバーが動いている | `https://<ドメイン>/healthz` を開く。`"ok":true,"db":true` なら正常 |
| バックアップが取れている | `data/backups` に、当日の日付のファイルがある |
| 配信エージェントがつながる | 進行コンソールの「配信エージェント」が「接続中」 |
| 配信が始まる | 品を1つ追加して開始し、「OBS」が「配信中」になり、入札画面に映像が出る |
| カメラを切り替えられる | 進行コンソールの「カメラ」のボタンを順に押し、入札画面の映像が切り替わる（6章） |
| 音声が出る | 入札画面で「音声を出す」を押して、会場の音が聞こえる |
| 入札と締め | 別の端末2台で入札し、締めて、落札の表示が出る |

ソフトウェアの入れ替えは、開催日の前日から開催の終了まで行わないでください（本仕様 NFR-REL-003）。

## 2. バックアップと復元

毎日1回取り、7世代を残します（本仕様 DATA-004）。サーバーを止めずに取れます。

```bash
node tools/backup.js
```

cron の例（毎日 3:00）:

```
0 3 * * * cd /opt/auction-poc && /usr/bin/node tools/backup.js >> /var/log/auction-backup.log 2>&1
```

復元は、サーバーを止めてから行います。いまのデータベースは消さずに、名前を変えて残します。

```bash
sudo systemctl stop auction-poc
```

```bash
node tools/backup.js --restore data/backups/auction-20261116-030000.db
```

```bash
sudo systemctl start auction-poc
```

バックアップは同じサーバーの中に置かれます。サーバーごと失う場合に備えるには、`--dir` で別の場所（別のディスクや、別のサーバーに同期されるフォルダ）を指定してください。

## 3. 開催中に起きたとき

| 起きたこと | 画面の様子 | やること |
|---|---|---|
| サーバーが落ちた | 全員の画面に「再接続中」 | 自動で起動し直すのを待つ（数秒）。戻ると、受付中だった品は「中断」になっている。入札は残っているので、状況を説明してから「再開」を押す |
| 締めた直後に落ちた | 同上 | 戻ると、締めは確定している（やり直さない）。結果を確かめて、次の品へ進む |
| 配信が始まらない | 板に「配信が始まりません（60秒経過）」 | OBS が起動しているか、配信用PCのネットワークを確かめる。待てないときは「映像なしで開始」。直してからやり直すなら「待機に戻す」 |
| 配信エージェントが切れた | 「配信エージェント」が「未接続」 | 配信用PCのネットワークを確かめる。エージェントは自動でつなぎ直す。切れている間、OBS の配信は止まらない |
| 会場の Wi-Fi が切れた | 会場の参加者の画面に「再接続中」 | 「中断」を押す。Wi-Fi が戻り、参加者の画面が戻ったのを確かめてから「再開」 |
| 1人だけつながらない | その人の画面に「再接続中」 | 競りは止めない（本仕様 FR-CLS-004）。電波の良い場所に移ってもらう |
| 間違えて品を開始した | 受付中になった | 入札がなければ、そのまま「締め」（流札になる）。入札があるなら「中断」→「取りやめ」（理由の入力が要る。入札はすべて無効になり、品は待機に戻る） |
| 不適切なコメント | 進行コンソールの「参加者のコメント」 | 「非表示」を押す。全員の画面から消える（記録は残る） |
| 配信を止め忘れた | 「競りがないまま ○ 分、配信が続いています」 | 休憩に入るなら「配信を停止」。次の品を始めれば、自動でまた始まる |

## 4. 守りの設定

既定の値で、想定（同時 100 人）の範囲では参加者に影響しません。値は環境変数で変えられます。

| 守り | 既定 | 超えたとき |
|---|---|---|
| 同時接続の上限 | 500 | 新しい接続を断る |
| 同じ人の同時接続 | 5 | 6つ目を断り、画面に理由を出す |
| 入札の速さ（会員ごと） | 1秒に5回 | 超えた入札を「入札が速すぎます」で返す。順番や記録には入れない |
| 受信の速さ（接続ごと） | 1秒に100件 | 接続を切る |
| 名乗らない接続 | 10秒 | 接続を切る |
| 送信の滞留 | 1MB | その端末を切る（端末はつなぎ直して、最新の状態を取り直す） |
| よそのサイトからの接続 | 断る | 別のドメインから使うときは `POC_ALLOWED_ORIGINS` に足す |

映像が出ないときは、読み込みの制限（Content-Security-Policy）が原因の可能性があります。ブラウザの開発者ツールに「Content Security Policy」を含むエラーが出ていれば、`POC_CSP=off` で外して確かめてください（映像の再生に要る許可は、実物で未確認です）。

## 5. 開催の後

1. 「配信を停止」を押す（開催終了の操作は PoC にありません）。
2. バックアップを取る。
3. 測定の記録（`data/metrics`）を控える。全体が 1GB を超えると、古い分から消えます。

## 6. カメラのつなぎ方（スマホ・無線カメラ・USB カメラ）

カメラは、配信用PCの OBS につなぎます。入札サーバーは、OBS の**どのシーンを映すか**を切り替えるだけで、カメラの映像そのものには触れません（報告書 92 章）。

### 6.1 共通の準備

1. OBS で、カメラごとにシーンを1つずつ作り、名前を「カメラ」で始めます（例: 「カメラ: スマホ」「カメラ: 無線」「カメラ: USB」）。
2. それぞれのシーンに、下の 6.2〜6.4 のやり方でカメラの映像を入れます。
3. 配信エージェントがつながると、進行コンソールの「配信」の欄に、カメラのボタンが OBS と同じ順で並びます。押すと、配信を止めずに切り替わります。いま映しているカメラのボタンは塗りつぶされます。OBS の画面で手で切り替えた場合も、進行コンソールに反映されます。
4. 「カメラ」で始まらないシーン（休憩の画面など）は、進行コンソールに出ません。始まりの言葉は、配信用PCの `agent/.env` の `AGENT_CAMERA_PREFIX` で変えられます。

- 入札画面のライブ画面は 4:3 です。OBS の「設定 → 映像」の基本解像度と出力解像度を 4:3（例: 1440×1080）にし、各シーンのカメラ映像を、画面いっぱいに合わせてください。16:9 のままだと、上下に黒い帯が出ます。
- カメラのパスワードや URL は、OBS の中だけに入れます。入札サーバーには送りません。

### 6.2 USB カメラ（有線）

| カメラ | つなぎ方 | OBS での入れ方 |
|---|---|---|
| USB の Web カメラ | PC の USB につなぐ。UVC 対応の機種は、多くの場合ドライバなしで使える | ソースの「＋」→「映像キャプチャデバイス」→ デバイスを選ぶ |
| ビデオカメラ・一眼カメラ（HDMI 出力） | カメラの HDMI 出力を、HDMI→USB のキャプチャ機器を通して PC の USB につなぐ | 同上（キャプチャ機器の名前を選ぶ） |

### 6.3 スマホのカメラ

| やり方 | つなぎ方 | OBS での入れ方 |
|---|---|---|
| Mac と iPhone | 連係カメラ（Continuity Camera）を使う。Mac と iPhone を同じ Apple アカウントにし、iPhone を固定する | 「映像キャプチャデバイス」で iPhone を選ぶ |
| Windows（iPhone・Android） | スマホと PC の両方に、スマホを Web カメラにするアプリ（例: Camo、DroidCam、Iriun など）を入れる。**USB でつなぐと、Wi-Fi より途切れにくい** | 「映像キャプチャデバイス」で、アプリのカメラを選ぶ |
| スマホから映像を送る（SRT） | スマホに、SRT で送れる配信アプリ（例: Larix Broadcaster）を入れ、送り先を `srt://<配信用PCの IP アドレス>:9000` にする。PC のファイアウォールで、このポートを会場の LAN にだけ開ける | ソースの「＋」→「メディアソース」→「ローカルファイル」を外し、入力に `srt://0.0.0.0:9000?mode=listener` |

- スマホは、通知・着信・画面の自動ロックを切り、充電しながら使ってください。

### 6.4 無線カメラ

| カメラ | つなぎ方 | OBS での入れ方 |
|---|---|---|
| ワイヤレス映像伝送機（HDMI の送信機と受信機） | カメラの HDMI 出力を送信機につなぎ、受信機の HDMI を、HDMI→USB のキャプチャ機器で PC につなぐ | 「映像キャプチャデバイス」（6.2 と同じ） |
| Wi-Fi のネットワークカメラ（RTSP 対応） | カメラと配信用PCを、同じ LAN につなぐ。RTSP の URL は、カメラの説明書を見る | 「メディアソース」→「ローカルファイル」を外し、入力にカメラの RTSP の URL（例: `rtsp://ユーザー:パスワード@192.168.1.50:554/…`） |

### 6.5 選び方の目安

- 競りでは、映像の遅れが入札の遅れにつながります。**メインのカメラは有線（USB、または HDMI のキャプチャ機器）**をすすめます。ワイヤレス映像伝送機も、Wi-Fi を使わないので、遅れが小さい機種が多いです。
- Wi-Fi を使うもの（スマホの Wi-Fi 接続、ネットワークカメラ、SRT）は、会場の Wi-Fi が混むと途切れます。使うときは、参加者が使う Wi-Fi と分けてください。
- 切り替え用に、2台目のカメラを別のシーンに入れておくと、1台が止まったときに進行コンソールからすぐ切り替えられます。
- 【未検証】上の手順は、この開発環境に実物がないため、実機では確かめていません。とくに、スマホ用アプリの名前と使い方、SRT の受け方、RTSP の URL は、機種やバージョンで変わります。開催の前に、使うカメラで、映像が出ること・遅れ・切り替えをリハーサルしてください。

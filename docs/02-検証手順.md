# 実物での検証の手順

この開発環境には AWS・OBS・スマホがないので、ここから先は実物が要ります。PoC 仕様書 5章の表の ID ごとに、やることを書きます。

## 0. 準備

| 要るもの | 使いみち |
|---|---|
| AWS のアカウント（東京リージョン） | Lightsail 1台（メモリ 2GB【提案値】）、IVS のチャンネル（Advanced HD）、EventBridge |
| PoC 用のドメイン（https） | スマホでの検証と、EventBridge の受け口（POC-OQ-04） |
| 配信用PC（本番と同じ OS）と OBS Studio 28 以降、カメラ | P1 |
| iPhone と Android を各1台以上、Wi-Fi と 4G／5G の回線 | P3、P2-10 |
| 負荷をかけるマシン（サーバーとは別の Linux） | P2-6〜P2-9 |

1. Lightsail にこのリポジトリを置き、`npm install`、`node tools/seed.js --members 300` を実行する。
2. `infra/auction-poc.env.example` を `/etc/auction-poc.env` に写して値を入れ、`infra/auction-poc.service` と `infra/Caddyfile` を入れて起動する。
3. サーバーの時計のずれを記録する（`chronyc tracking`）。PoC の終わりにも記録する。
4. IVS のチャンネルを作る。ストリームキーは OBS の「配信」設定にだけ入れる。チャットやファイルに貼らない。
5. `infra/eventbridge.md` の手順で EventBridge を設定する。
6. 配信用PCで、OBS の WebSocket サーバーを有効にし、`agent/.env` を作って `node src/agent.js` を起動する。
7. Lightsail のファイアウォールで、接続元を PoC の関係者の IP アドレスに絞る（PoC 仕様書 11章）。4G／5G の検証の間だけは絞れないので、トークンつきの URL だけで守る。

進行コンソールの「測定開始の印」「測定終了の印」に検証の ID（例: `P1-1`）を入れて押すと、その間の記録だけを `node tools/aggregate.js --label P1-1` で集計できます。

## 1. P1 配信の自動制御

| ID | やること | 見るところ |
|---|---|---|
| P1-1 | 配信が止まった状態で、ロットを追加して「競り開始」。受付中になったら「締め」を押し、「配信を停止」で配信を止める。20回くり返す | 集計の「配信の自動開始」。60秒以内に LIVE か。方法 (a)(b) の差。入札画面の映像が、受付中になる時点で映っているか（8秒の待ち時間に収まるか）を、1回分は動画で記録する |
| P1-2 | **対象外**（配信の自動停止をやめたため。報告書 12 章）。代わりに、落札の後も配信が続くことと、「配信を停止」で止まることを確かめる | 進行コンソールの OBS の表示、入札画面の映像 |
| P1-3 | 配信用PCのネットワークを30秒止めて戻す。配信中と停止中の両方 | 進行コンソールの「配信エージェント」が未接続 → 接続中に戻るか。OBS の表示が実際と合うか。配信中に切っても OBS の配信が続くか（回線が切れているので IVS への送信自体は途切れる。OBS が配信をやめないことを見る） |
| P1-4 | OBS を終了して「競り開始」 | 60秒後に「配信準備中（警告）」になり、「映像なしで開始」「待機に戻す」を選べるか |
| P1-5 | 進行コンソールを別のPC・タブレットで開いて P1-1 を5回 | P1-1 と同じ |
| P1-6 | AWS の請求画面で、IVS の送信時間と視聴時間を控える | 報告書に書く |

## 2. P2 性能と締めのタイムラグ

正しさ（P2-1〜5）は `npm test` で確かめます。Lightsail の上でも1回実行して、結果を残してください（ディスクの fsync の速さが違うため）。

| ID | コマンド（負荷をかけるマシンで） | 備考 |
|---|---|---|
| P2-6 | `node tools/load.js --url wss://<ドメイン>/ws --clients 100 --lots 30 --label P2-6` | サーバーは `POC_IVS_MODE=always-live` で起動し直す（配信なしで競りだけ回す） |
| P2-7 | `sudo tools/netem.sh on eth0` の後に、ラベルを `P2-7` にして同じコマンド。終わったら `sudo tools/netem.sh off eth0` | 再接続の回数は load の出力に出る |
| P2-8 | `--clients 300 --lots 10 --label P2-8` | CPU・メモリは集計に出る |
| P2-9 | `--clients 20 --lots 54 --interval 600 --burst 10 --label P2-9` | 9時間。メモリの傾きと、前半・後半の平均を見る |
| P2-10 | 実機（Wi-Fi と 4G／5G）で入札画面を開いたまま、進行コンソールで「締め」を各30回。入札画面の URL に `&net=wifi` や `&net=5g` を付ける | 集計の「進行役が押してから各端末に結果が出るまで」が回線ごとに出る。5回分は動画で記録する |
| P2-11 | P2-6 の集計の「締めの前1秒以内に端末が送っていたもの」 | 判定には使わない |

## 3. P3 スマホの実機

入札画面の下の「検証用の情報」を開くと、画面を消さない機能・音・振動・映像の遅延・入札の応答時間が出ます。同じ内容がサーバーの記録にも残ります。

| ID | やること |
|---|---|
| P3-1 | 「参加する」を押した後、別の端末から上回る。10分放置した後にも試す。音が鳴ったかを控える |
| P3-2 | 同じ操作で振動したかを控える |
| P3-3 | 「画面を消さない機能」が「有効」か。30分放置して画面が消えないか |
| P3-4 | 映像を表示したまま30分。集計の「映像の遅延」。「取れない」と出る場合は、進行コンソールのサーバー時刻をカメラで映し、入札画面のサーバー時刻と並べて写真に撮る |
| P3-5 | 機内モードを10秒。Wi-Fi から 4G への切り替え。集計の「再接続」の `sinceOnlineMs` が 10,000 以下か、戻った後の価格・権利表示が正しいか |
| P3-6 | タブを裏に回して戻す。画面をロックして戻す |
| P3-7 | 入札ボタンを Wi-Fi と 4G／5G で各50回。集計の「入札ボタンから結果の表示まで」 |

## 4. 片付け（PoC 仕様書 11章）

IVS のストリームキーを作り直す。Lightsail の検証用のデータ（`POC_DATA_DIR`）を、測定の記録を手元に写してから消す。IAM のキーと EventBridge の設定を消す。

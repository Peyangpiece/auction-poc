# UX の評価と改善（2026-11-16）

対象は、入札画面（`web/bidder.html`）と進行コンソール（`web/console.html`）。
見た目ではなく、「使う人が、迷わず・間違えず・状況が分かるか」を評価した。

評価の方法は2つ。

1. **実測**: ヘッドレスのブラウザで、端末の幅ごとに機械的に測った（横あふれ、押せる範囲、文字の大きさ、固定の板が画面を占める割合、キーボードの順路）。
2. **流れの追跡**: 使う人の立場で、入場から落札・切断までの流れを1歩ずつ追い、UX 監査の観点（発見しやすさ、頭の中のモデルとの一致、認知負荷、状態の伝え方、失敗からの復帰、段階的な開示、一貫性、取り消し）と、ニールセンの10項目に当てた。

**確かめていないこと**: 実際の人による使用テスト、実機（iPhone・Android）、スクリーンリーダーでの読み上げ。ここに書いた改善は、実測と追跡で見つけた問題への対応で、「使いやすくなった」ことを人で確かめたものではない。

## 1. 実測の結果

| 測ったもの | 改善前 | 改善後 |
|---|---|---|
| 横あふれ（320・360・390・640・740・1280px 幅） | 0 件 | 0 件 |
| 44px 未満の押せる範囲 | 0 件 | 0 件 |
| 12px 未満の文字 | 0 件 | 0 件 |
| 初めての人が入場した直後の入札ボタン | **押せない**（「観戦」で入るため。切り替えは画面の上端） | 押せる。押すと「応札」に切り替わる |
| 640×450（PC の 200% 拡大）で、固定の板が画面を占める割合 | **44%。映像が 244px 隠れる** | 板を固定しない。隠れは 0 |
| 740×360（スマホの横向き）の入場画面 | **「参加する」が画面の外にはみ出して押せない** | 中でスクロールできる。押せる |
| キーボードでの順路（PC） | コメント欄 → 入札ボタンの順 | 入札ボタン → コメント欄の順 |
| 固定の板の下の余白 | 256px の決め打ち（板の高さ 199〜216px とずれる） | 板の実際の高さに合わせて自動で取る |

## 2. 流れの追跡で見つけた問題と対応

### 入札画面（会員）

| # | 場面 | 問題 | 重さ | 対応 |
|---|---|---|---|---|
| 1 | 入場した直後 | 「観戦」で入るので入札ボタンが押せず、切り替えの場所（上端）を探す必要がある | 高 | 観戦中の入札ボタンを「応札に切り替える」ボタンにした。1回目の押下では切り替えるだけで、入札はしない |
| 2 | 入札しようとした瞬間に、他の人が入札した | ボタンの金額が指の下で上がり、古い金額のつもりで新しい金額を押してしまう | 高 | 他の人の入札で金額が変わった直後の 0.6 秒は、ボタンを押せなくする |
| 3 | 入札の結果が出た後 | 「受理されました」「価格が更新されました」が、状況が変わった後も残り続ける | 中 | 他の人の入札が届いたら、前の結果の表示を消す |
| 4 | 入札を送った直後に通信が切れた | 10 秒待たされたうえ、「応答がありません」とだけ出る。入札が届いたかどうか分からない | 高 | 切れた時点ですぐ「通信が切れました。入札が届いたかは、つながり直した後の表示で確かめてください」と出す |
| 5 | つながり直した後 | 画面が最新になったのか分からない | 中 | 「つながり直しました。最新の状態を表示しています」と出す |
| 6 | 自分が落札した | 「1番 落札」とだけ出て、自分のことだと気づきにくい | 中 | 「あなたが落札しました」と出し、音と振動でも知らせる |
| 7 | 入場した直後、サーバーにつながる前 | 「次のロットをお待ちください」と出て、つながっているように見える | 低 | つながるまでは、入札ボタンに「接続しています…」と出す |
| 8 | 入札の履歴・コメントを読み返している途中 | 新しい行が届くたびに、いちばん下まで勝手に動く | 中 | いちばん下を見ているときだけ追従する |
| 9 | コメントを書いている途中 | 20 文字で黙って入力が止まる | 低 | 「12／20文字」と残りを出す |
| 10 | 初めて見る人 | 「うりきり」「権利」の意味を知る機会が、画面の下の注記だけ | 中 | いったん入場画面に説明を足したが、6 章の文言の整理で削除した。意味は会場での説明に委ねる（発注者の指示） |
| 11 | 別のタブを見ている間 | 価格の動きも、上回られたことも分からない | 低 | タブの題名に現在価格を出し、上回られたら題名を変える |
| 12 | 画面の読み上げを使っている人 | 入札が続くと、価格とランプの変化がすべて読み上げられ、あふれる | 中 | 逐一の読み上げをやめ、「上回られた」「落札」「流札」だけを知らせる |

### 進行コンソール（進行役）

| # | 場面 | 問題 | 重さ | 対応 |
|---|---|---|---|---|
| 13 | 締めた後 | 次のロットを始めるには、板から目を離して、下の一覧から行を探す必要がある | 高 | 板のすぐ下に「次のロットを開始（No.○）」を出す。締めた後にやることが1つだけになる |
| 14 | 操作が拒否された | 理由が、右の「操作の記録」にしか出ない | 中 | 操作したボタンのすぐ下にも理由を出す |
| 15 | 「締め」を素早く2回押した | 2回目は拒否されるが、記録に誤りの行が残る | 低 | 結果が届くまでボタンを押せなくする |
| 16 | 進行中に、一覧の「競り開始」が押せない | 押せない理由が分からない | 低 | 「進行中のロットを締めてから開始できます」と示す |

## 3. そのままにした点（判断が要るもの）

| 点 | そのままにした理由 |
|---|---|
| 入札が1回の押下で確定する | PoC 仕様書（POC-UI-002）が、PoC では1回の押下でよいとしている。本番は2段階（金額の確認 → 長押し）と決まっている（FR-BID-002・006）。#2 の 0.6 秒は、その間の誤入札を減らす手当て |
| 「締め」に確認を挟まない | 締めは「進行役の操作をサーバーが受け付けた時点で確定」と決まっており（決定 v0.12）、確認を挟むと締めが遅れる。代わりに、板に「いま締めると、○番が落札します」と結果を先に示している |
| スマホで、表示板が画面の約3割を占める | 価格・ランプ・入札ボタンを常に見せるため。4:3 の映像と合わせると、履歴は少しスクロールが要る |
| 最初は「観戦」で入る | 誤入札を防ぐため。#1 で、切り替えの手間は1回の押下にした |

## 4. ニールセンの10項目（改善後の自己採点、0〜4）

自己採点であり、人による評価ではない。

| 項目 | 点 | 根拠と、残っている弱み |
|---|---|---|
| 状態が見える | 4 | 接続・受付・ランプ・入札の結果・切断と復帰を、その場で示す |
| 現実の言葉に合う | 3 | 競りの言葉（うりきり・権利・締め）を使う。初めての人には入場画面で説明するが、会場での口頭の説明も要る |
| 自由と取り消し | 2 | 入札は取り消せない（決定）。観戦への切り替えはいつでもできる |
| 一貫性 | 4 | 板・ランプ・ボタンの形と言葉が、2つの画面で同じ |
| 間違いの予防 | 3 | 観戦で入る、金額が変わった直後は押せない、二度押しを防ぐ。入札の2段階の確定は本番で入る |
| 覚えずに分かる | 4 | 次にやることがボタンの文言に出る（「¥12,000 で入札」「次のロットを開始（No.2）」） |
| 柔軟さと効率 | 3 | 進行役は板の下の1つのボタンで進められる。キーボードの近道はない |
| 最小限の見た目 | 4 | 情報は1か所ずつ。その状態でできる操作だけを出す |
| 失敗からの復帰 | 3 | 拒否の理由と次の金額を示す。切断中の入札は、復帰後の表示で確かめる形 |
| 手助け | 2 | 入場画面の3行と注記だけ。使い方のページはない |

## 5. 次に確かめるとよいこと

1. 実機での使用テスト（会場参加の人 3〜5 人、オンラインの人 3〜5 人）。見るところ: 入場から最初の入札までの時間、誤入札の有無、ランプの意味が伝わるか。
2. 0.6 秒の押下の停止が、速い競りの邪魔にならないか（P3-7 の測定と合わせて見る）。
3. スクリーンリーダー（VoiceOver・TalkBack）での読み上げ。

## 6. 文言と表示の整理（発注者の指示: 無駄な文や表示はすべて削除）

同じことを2か所で言っているもの、無くても状態が分かるものを削った。

| 削ったもの | 削った理由 |
|---|---|
| 入場画面の説明の箇条書き（4行） | 注意書きは入札画面の下に1か所あれば足りる |
| 映像の枠の補足（「入札の受付が始まると…」）、再接続中の補足 | 見出しの1行で分かる |
| 「うりきり」のランプの下の文（「最低落札額に未達」など） | ランプの点灯・消灯が同じことを示している |
| 「権利」のランプの下の「最高入札者」の語 | 番号だけで分かる |
| 板の案内の行のうち、「最低落札額に届くまで…」「中断しています…」「次のロットの開始を…」 | ランプ・状態の表示・入札ボタンの文言と重なる |
| 「応札に切り替えました。もう一度押すと…」 | ボタンの文言が「¥○ で入札」に変わることで分かる |
| 履歴・コメント・ロット一覧・記録の「まだありません」 | 件数の「0件」や空の表で分かる |
| コメント欄の「（20文字まで）」 | 横の「0／20」で分かる |
| 「「うりきり」と「権利」の両方が点いている人が落札します」「最低落札額の金額は表示されません」 | 発注者の指示。意味は会場での説明に委ねる |
| 進行コンソールの「LIVE の判定」の行と「状態を問い合わせる」 | 測定用。折りたたみの「測定と障害の模擬」に移した |
| 進行コンソールの板の案内（「「次のロットを開始」を押すと…」「配信が始まるのを待っています」） | ボタンと状態の表示に重なる |

**残したもの**（仕様や安全のために要る）:

- 「落札価格に送料は含まれません」（本仕様 FR-SHIP-003 が入札画面への表示を求めている）
- 「締めの直前の入札は、通信の遅れで間に合わないことがあります」（FR-CLS-004）
- 入札の受理・拒否の表示（FR-UI-003）、落札の表示（FR-UI-007）、再接続中の表示（FR-UI-001）
- 進行コンソールの「締めると ○番が落札」「締めると流札」（締めは取り消せないので、結果を先に示す）
- 取り消せない操作の確認の文
- 「検証用の情報」「測定と障害の模擬」（PoC の測定に使う。ふだんは折りたたまれている）

**削ったことの影響**: 4 章の自己採点のうち、「現実の言葉に合う」と「手助け」は下がる方向（初めての人への説明が画面からなくなったため）。「最小限の見た目」は上がる方向。

# UX Audit: 令和の競り（全画面・現状）

**Perspective**: UX Engineer
**Date**: 2026-11-18
**Plan**: リポジトリの現状（web/ の全画面。ブランチ claude/vigilant-wozniak-jhrqv6、6063927 以降）
**方法**: ローカルで起動し、画面を状態ごとに撮って（iPhone・iPhone SE・Pixel・横向き・PC・ダーク）見た。判定の理由は、画面だけでなく web/caller.js・web/bidder.js の分岐も読んで確かめた。

## Plan Summary
会員（オンライン・会場）、オークショニア（スマホ）、進行役（PC のコンソール）、管理者・受付、会場モニターの画面がある。説明文を減らした直後なので、「なぜ押せないか」「入力が使われたか」を画面が自分で伝えているかを重点に見た。

## User Journey Map

### 1. 新しい会員（登録 → ログイン）
| 手順 | 状態 | 所見 |
|---|---|---|
| 電話番号を入れる | OK | 1画面1項目で迷わない |
| 確認コード（SMS） | OK | 「…に送りました。5分以内に」・送り直しがある |
| 会員情報の入力 | OK | 郵便番号から住所、配送先の同じ、の順が自然 |
| ログイン（ID とパスワード） | WARN | パスワードの決まりが入力欄の中の薄い字（placeholder）だけ。打ち始めると消える |
| マイページ「メールアドレスの確認が済んでいません」 | OK | 次にやることが1つのボタンで出ている |

### 2. オンラインの入札者
| 手順 | 状態 | 所見 |
|---|---|---|
| ホームで落札結果・次の開催を見る | WARN | 下のタブバー（ガラス）が「次の開催」の行に重なり、文字が透けて読みにくい |
| 競りの画面に入る（品を待つ） | WARN | 配信が「放送中」なのに再生先の URL がないと、「映像を準備しています」が時間の制限なく出続ける（bidder.js renderStream）。壊れているように見える |
| 入札する | OK | 入札ボタンと金額がはっきりしている |
| 最高入札者になる | WARN | 状態の名前が「権利」。業界の言葉で、初めての人は意味が分からない。下に「あなたが最高入札者です」が出るので致命的ではない |
| 中断 | OK | 「中断しています」が出る |
| 落札 → 次の品を待つ | OK | 「あなたが落札しました」「次の品をお待ちください」 |
| 請求書を開く | OK | 期限・金額・PDF のボタンが1枚にまとまっている |
| 下のガラスの帯の後ろの文字 | WARN | 「参加のしかた: オンライン参加」などが帯の後ろで薄く透けて、読めそうで読めない |

### 3. 会場の入札者
| 手順 | 状態 | 所見 |

| 来場確認 → 札で入札 | OK | 画面での入札はできず、受付・代理入札の流れ |
| 来場確認がまだの人の代理入札 | OK | コンソールに理由が赤字で出る |

### 4. オークショニア（スマホ）
| 手順 | 状態 | 所見 |
|---|---|---|
| 次の品が来る（開始値あり） | OK | 「No.2 を開始 ¥3,000」の1ボタン |
| 次の品が来る（品名だけ） | OK | 開始値のシートが自動で開く |
| シートを「あとで」で閉じる | WARN | 開始値を入れる場所が2つになる（上の「開始値」欄＋「変更」、下の「開始値を入れて始める」）。どちらを使えばよいか迷う |
| 開始前に開始値を変える | **FAIL** | 欄に新しい金額を入れて「変更」を押さずに「No.1 を開始」を押すと、**古い金額で始まる**。入れた数字は黙って捨てられる（caller.js: `cmd('start')` は欄の値を送らない） |
| 受付中に締める | OK | 「→ 1番 ¥9,000 落札」「→ 流札」で結果が先に分かる。確かめのダイアログもある |
| うりきり済みで流札を押したい | **FAIL** | 流札が灰色になるだけで、理由が出ない（入札がうりきりに届いているため）。現場で「押せない、壊れた？」となる |
| うりきりのボタンが灰色 | WARN | 上の「うりきりまで 済み」が理由だが、ボタンとは離れていて結びつきにくい |
| 中断 → 再開 | OK | 中断は上の帯、再開は下の大きなボタン。押した直後の場所に次の操作が出る |
| 「うりきりまで 済み」（最低落札額なしの品） | WARN | 最低落札額が最初からない品でも「済み」。「なし」の方が事実に合う |

### 5. 進行役（PC のコンソール）

| 「開催終了…」 | WARN | 赤いボタンが、ふだん使う「休憩に入る」の真下にある。押し間違えやすい位置（確かめはある） |

## Verdict: APPROVE WITH CHANGES

迷いが金額や落札結果に直接つながる箇所が2つある（下の Critical）。それ以外は、次にやることが1つずつ出る作りになっていて、大きな作り直しは要らない。

## Critical Issues (Must Fix)
| # | Issue | Step in Journey | Impact on User | Fix |
|---|-------|----------------|----------------|-----|
| 1 | 開始前に欄へ入れた開始値が、「変更」を押さないと使われない。大きなボタンの小さな字は古い金額のまま | 4. 開始前に開始値を変える | 意図と違う金額で競りが始まる。入札が入ると、もう直せない | 開始前は「変更」をなくし、大きなボタンが欄の金額で始める（`start` に amount を付ける。サーバーは既に対応）。ボタンの小さな字も欄の値に合わせて動かす |
| 2 | 流札が押せない理由が出ない（うりきりに届いた入札があるとき） | 4. うりきり済みで流札 | 競りの最中に手が止まる。進行役に聞きに行く | 押せないときは、ボタンの小さな字に「うりきり済み」と出す。あるいは、押したら理由を1行出す。※流札をこの場合も許すかは、前に伺った点（未回答） |

## Recommendations
| # | Issue | Impact | Fix |
|---|-------|--------|-----|
| 3 | 品名だけの品で「あとで」を押すと、開始値の入口が2つになる | どちらに入れるか迷う | 開始値が未定の間は、上の「開始値」欄を隠し、下のボタン1つにする |
| 4 | 「映像を準備しています」が出続ける（放送中の印があり、再生先がないとき） | 「壊れている」と思われる | 一定時間たっても映像が来なければ「映像はありません。価格と入札はこの画面で続けられます」に変える。配信を使わない開催では枠ごと出さない |
| 5 | 「権利」という言葉 | 初めての人に意味が通じない | 「最高入札」に変える（下の「あなたが最高入札者です」と言葉をそろえる） |
| 6 | ガラスの帯（入札者の下の帯・ホームのタブバー）の後ろで文字が透ける | 読めそうで読めない文字は、読もうとして目が止まる | 帯の不透明度を上げる、または帯の高さ分だけ下に余白を足して、文字が帯の後ろに来ないようにする |
| 7 | パスワードの決まりが placeholder だけ | 打ち始めると消え、エラーで初めて知る | 欄の下に短く常に出す（「8文字以上」など1行） |
| 8 | 受付タブの「本日の開催はありません。」 | 次に何をすればよいか分からない | 「開催を作る」へのリンクを添える |
| 9 | 「開催終了…」が「休憩に入る」のすぐそば | 押し間違い（確かめで止まるが、心臓に悪い） | 開催の操作の右端に離す、または「その他」の中へ |

## Nice-to-Haves
| # | Suggestion | Rationale |
|---|------------|-----------|
| 10 | 「うりきりまで 済み」→ 最低落札額がない品は「なし」 | 事実に合わせる |
| 11 | 「次の開始予定」に、どこに出るかの1語（例: 欄名を「モニターに出す再開時刻」） | 入力の目的が分かる |
| 12 | オークショニアの灰色のボタン全般に、短い理由（「受付前」「済み」など）を小さな字で | 説明文を増やさずに、押せない理由だけを伝える |

## Interaction Consistency Check
- 「次にやることを、押した場所に1つだけ出す」（オークショニアの下の大きなボタン、マイページの確認メール）は一貫していて良い。
- 例外が開始値の欄。ほかの操作は「1回押せば反映」なのに、ここだけ「入れて → 変更 → 開始」の2段で、2段目を飛ばすと黙って捨てられる。
- 確かめのダイアログは、取り消せない操作（締め・流札・うりきり・開催終了）だけに出ていて、中断・開始には出ない。方針どおりで一貫している。
- 灰色のボタンの理由: 入札者の画面は文で状態を伝えるが、オークショニアの画面は灰色だけ。画面ごとに伝え方が違う。

## Verdict Details
- Discoverability: PASS（主な操作は大きく、最初に目に入る位置）
- Flow Completeness: CONCERNS（開始値の欄の入力が捨てられる。#1）
- Error Recovery: CONCERNS（押せない理由が出ない。#2・#12）
- Feedback & Status: CONCERNS（映像の「準備しています」が終わらない。#4）
- Consistency: CONCERNS（開始値だけ2段の操作。灰色の理由の伝え方が画面ごとに違う）

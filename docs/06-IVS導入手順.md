# 映像（Amazon IVS）の導入手順

本番（Cloudflare）に、ライブ映像をつなぐための手順です。いまの本番は、IVS の設定がないため、映像なしで競りだけを動かしています（`POC_IVS_MODE=always-live`）。

実物（AWS・OBS・カメラ）での確認はまだ済んでいません。初回は、本番の前に必ずリハーサルで通してください。【未検証】の印は、公式の資料か実物で確かめる必要がある箇所です。

## 0. 全体の流れ

```
カメラ → 配信用PC（OBS ＋ 配信エージェント） → IVS → 参加者の入札画面
                    │                              ↑
                    └─ 外向きにつなぐ → 入札サーバー ─┘ LIVE かどうかを IVS に問い合わせる
```

| 段 | だれが | どこで | かかる時間の目安 |
|---|---|---|---|
| 1. IVS のチャンネルを作る | 管理者 | AWS のコンソール | 15 分 |
| 2. 問い合わせ用の鍵を作る | 管理者 | AWS のコンソール（IAM） | 15 分 |
| 3. 本番に設定を入れて配る | 管理者 | GitHub の Secrets | 10 分 |
| 4. 配信エージェントの合言葉を用意する | 管理者 | GitHub の Secrets | 5 分 |
| 5. 配信用PCを用意する | 会場の担当 | 配信用PC | 1〜2 時間 |
| 6. リハーサル | 全員 | 会場 | 1〜2 時間 |

## 1. IVS のチャンネルを作る（AWS）

1. AWS のコンソールで、リージョンを**アジアパシフィック（東京）**にする。本番の入札サーバーは、東京のチャンネルだけに問い合わせる（`AWS_REGION` の既定値が `ap-northeast-1`）。
2. Amazon IVS の画面で「低レイテンシーストリーミング」→ チャンネルを作る。

| 項目 | 選ぶもの | 理由 |
|---|---|---|
| チャンネルの種類 | **スタンダード** | 回線の弱い視聴者向けに、画質を自動で下げてくれる |
| レイテンシー | **低レイテンシー** | 競りでは、映像の遅れが入札の遅れになる |
| 再生の認可（プライベートチャンネル） | **使わない** | アプリは、再生のトークンに対応していない。再生用の URL を知っている人は、だれでも映像を見られる |
| 録画 | 使わない | 必要になったら、別に決める（S3 の料金がかかる） |

3. 作ったチャンネルの画面から、次の 4 つを控える。

| 控えるもの | 使い道 | 扱い |
|---|---|---|
| チャンネルの ARN | 入札サーバー（3 章） | 秘密ではないが、Secrets に入れる |
| 再生用の URL（`…m3u8`） | 入札サーバー（3 章） | 秘密ではない。ただし知られると、だれでも見られる |
| 取り込みサーバー（Ingest server） | OBS（5 章） | — |
| ストリームキー | OBS（5 章）**だけ** | **秘密。** チャット・メール・Secrets に入れない。漏れたら、IVS の画面で作り直す |

## 2. 問い合わせ用の鍵を作る（AWS の IAM）

入札サーバーは、1 秒ごとに IVS に「いま LIVE か」を問い合わせて、受付中にする時を決めます。そのための鍵を作ります。

1. IAM で、このためだけのユーザーを作る（例: `reiwa-no-seri-ivs`）。コンソールへのログインは許さない。
2. 許可は、`ivs:GetStream` だけにする（対象は 1 章のチャンネルの ARN）。

```json
{
  "Version": "2012-10-17",
  "Statement": [{ "Effect": "Allow", "Action": "ivs:GetStream", "Resource": "<チャンネルの ARN>" }]
}
```

3. このユーザーのアクセスキーを作り、アクセスキー ID とシークレットを控える（**秘密**）。
4. AWS Budgets で、月の予算の通知を設定しておく（止め忘れや、思わぬ視聴の増加に気づくため）。

## 3. 本番に設定を入れて配る（GitHub）

1. GitHub のリポジトリの Settings → Secrets and variables → Actions に、次の 4 つを入れる（4 章の `AGENT_TOKEN` も、このときに一緒に入れる）。

| 名前 | 値 |
|---|---|
| `IVS_CHANNEL_ARN` | 1 章のチャンネルの ARN |
| `IVS_PLAYBACK_URL` | 1 章の再生用の URL |
| `AWS_ACCESS_KEY_ID` | 2 章のアクセスキー ID |
| `AWS_SECRET_ACCESS_KEY` | 2 章のシークレット |

2. 「Cloudflareに配って」で配る。4 つがそろっていると、本番は自動で映像ありの動き（`POC_IVS_MODE=aws`）に切り替わる。1 つでも欠けると、これまでどおり映像なしで動く。
3. 配ったあと、進行コンソールに「配信」の欄が出ることを確かめる（まだ「配信エージェント: 未接続」でよい）。

- 競りの最中は、配信の仕組みが配るのを断ります（全員の接続が切れるため）。開催のない時間に配ってください。
- EventBridge で IVS の知らせを受ける方法（`EVENTBRIDGE_SECRET`、`infra/eventbridge.md`）は、なくても動きます（問い合わせの方法だけで LIVE が分かる）。最初は入れなくてかまいません。

## 4. 配信エージェントの合言葉を用意する（GitHub）

配信用PCの配信エージェントは、この合言葉で本番につながります（報告書 94 章）。

1. 32 文字以上の乱数を作る。例（どちらか）:

```bash
openssl rand -base64 33
```

```bash
node -e "console.log(require('crypto').randomBytes(33).toString('base64url'))"
```

2. GitHub の Secrets に `AGENT_TOKEN` として入れる（3 章の 4 つと一緒に）。
3. 「Cloudflareに配って」で配る。起動のときに、この合言葉だけが配信エージェントとして登録される。前の合言葉は使えなくなる。
4. 同じ値を、配信用PCの `agent/.env` の `AGENT_TOKEN` に入れる（5.2）。

- **秘密です。** チャットやメールに貼らず、GitHub の Secrets と配信用PCの `.env` だけに置いてください。
- 漏れたとき・配信用PCを替えたときは、新しい乱数を Secrets に入れて配り直し、配信用PCの `.env` も入れ替えます。
- 32 文字に満たない値は、配るときに止まります（登録しません）。
- 3 章の IVS の 4 つがそろっていないと、合言葉も入れません（映像なしで動くため）。

## 5. 配信用PCを用意する（会場）

### 5.1 OBS

1. OBS Studio（28 以降。WebSocket の機能が入っている）を入れる。
2. 「ツール → WebSocket サーバー設定」で、サーバーを有効にし、**パスワードを設定**する。ポートは既定のまま（4455）。
3. 「設定 → 配信」
   - サービス: カスタム
   - サーバー: `rtmps://<1 章の取り込みサーバー>:443/app/`【未検証: 形は IVS の資料で確かめる】
   - ストリームキー: 1 章のストリームキー
4. 「設定 → 映像」: 基本（キャンバス）解像度を **4:3（1440×1080 か 960×720）**にする。出力解像度は、配信エージェントが 960×720 にそろえる（報告書 93 章）。
5. 「設定 → 出力」（詳細モード）: キーフレーム間隔を **2 秒**にする。映像のビットレートは、720p なら 3,000〜4,500 kbps くらいから試す【目安。IVS の推奨値で確かめる】。
6. カメラをつなぎ、カメラごとに「カメラ」で始まる名前のシーンを作る（運用の手順 6 章）。

### 5.2 配信エージェント

1. Node.js 22 を入れる。
2. このリポジトリの `agent` フォルダーを配信用PCに置き、そのフォルダーで `npm ci` を実行する。
3. `agent/.env.example` を `agent/.env` に写して、値を入れる。

| 名前 | 値 |
|---|---|
| `AGENT_SERVER_URL` | `wss://<本番のドメイン>/agent` |
| `AGENT_TOKEN` | 4 章の合言葉 |
| `OBS_URL` | `ws://127.0.0.1:4455`（そのまま） |
| `OBS_PASSWORD` | 5.1 の 2 で決めたパスワード |

4. `node src/agent.js` で起動する。開催の日に PC を起動したら自動で動くよう、Windows ならタスク スケジューラ、Mac ならログイン項目に登録しておく。
5. 配信用PCのポートは、開けなくてよい（エージェントは外向きにつなぐだけ）。

## 6. リハーサル（本番の前に必ず）

| 確かめること | やり方 | よい状態 |
|---|---|---|
| エージェントがつながる | 進行コンソールの「配信」の欄 | 「配信エージェント: 接続中」、カメラのボタンが並ぶ、「映像の大きさ: 960×720」 |
| 配信が自動で始まる | 品を追加して「開始」 | 配信準備中 → LIVE → 受付中（60 秒以内） |
| 映像が出る | オンライン参加でスマホと PC から入る | 映像が出る。音声を出せる |
| 遅れ | 会場で手を叩き、スマホの映像で見えるまでを測る | 数秒程度【目標値は発注者と決める】 |
| カメラの切り替え | 進行コンソールのカメラのボタンを順に押す | 配信を止めずに映像が替わる |
| 止め方 | 「配信を停止」 | 入札画面の映像が止まる。OBS も「停止」 |
| 回線が切れたとき | 配信用PCの LAN を 30 秒抜いて戻す | エージェントが自動でつなぎ直す |
| 費用 | 翌日、AWS の請求の画面 | 入力の時間と視聴の時間が、想定どおり（HD の区分になっているか） |

## 7. 当日の注意

- 配信は自動では止まりません。終わったら必ず「配信を停止」を押してください。止め忘れると、時間あたりの料金がかかり続けます（進行コンソールに注意が出ます）。
- 映像が出ないときは、まず進行コンソールの「配信エージェント」「OBS」の表示を見て、運用の手順 3 章に沿って対応してください。待てないときは「映像なしで開始」で競りを進められます。
- 再生用の URL を知っている人は、だれでも映像を見られます。気になる場合は、チャンネルを作り直して URL を変えられます（Secrets の `IVS_CHANNEL_ARN`・`IVS_PLAYBACK_URL` も入れ替えて、配り直す）。

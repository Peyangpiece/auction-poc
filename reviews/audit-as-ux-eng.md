# UX Audit: 令和の競り（参加者の一連の流れと、スタッフの操作）

**Perspective**: UX Engineer
**Date**: 2026-11-17
**Plan**: web/（実際に動かしたサーバーを、スマホ幅 390px とパソコン幅 1280px で操作して確認）

## Plan Summary
初めての参加者が、トップ → 会員登録 → 参加手続き → 入札 → 落札後の確認まで進む流れと、スタッフの管理・進行の画面を、実際に操作して点検した。

## User Journey Map
1. トップで「本日開催」と「参加する」を見つける — OK
2. 会員登録: 電話番号 → 認証番号 → お客様の情報（3段の表示つき） — OK（認証番号の入力後にボタンを押す手間があった → 直した）
3. 入力の途中でページを離れる — OK（離れる前の確かめを追加済み）
4. 参加手続き: 受け取り方法・支払方法を選ぶ。買歩銭・送料・返品の案内が同じ画面に出る — OK
5. 参加番号の表示 →「参加する」 — OK（番号を見せるための1画面。音と映像を始めるのに、利用者の操作が要る）
6. 入札の画面: はじめは「観戦」。「応札に切り替える」で入札できる — OK（押しまちがいを防ぐ作り）
7. 入札 → 最高入札者・追い越されたときの知らせ — OK（既存の通し確認で確認済み）
8. 落札後: マイページに請求と期限が出る — OK
9. 無いページを開いた — FAIL だった（素の英語だけ）→ 案内のページを追加して OK
10. 規約を読む — FAIL（3つとも「準備中です。」。文面は発注者の用意が要る）

## Verdict: APPROVE WITH CHANGES

## Critical Issues (Must Fix)
| # | Issue | Step in Journey | Impact on User | Fix |
|---|-------|----------------|----------------|-----|
| 1 | 規約類が「準備中」 | 10 | 条件が分からないまま登録・入札することになる。公開の要件を満たさない | 発注者が文面を用意し、管理の「設定」から入れる（未了） |
| 2 | SMS が届かない（お試し用の設定で、認証番号が画面に出る） | 2 | 本物の本人確認にならない | SMS の送信サービスを契約してつなぐ（未了） |
| 3 | 無いページが素の英語 | 9 | 行き止まりになる | 案内のページを追加（済み） |
| 4 | 進行コンソールに「サーバーを強制終了する」ボタンが見えている（無効だが、開発者向けの説明つき） | スタッフ | 本番の進行役を不安にさせる。押しまちがいの心配 | 検証用の環境でだけ出す（済み） |

## Recommendations
| # | Issue | Impact | Fix |
|---|-------|--------|-----|
| 1 | 認証番号を入れたあと、もう一度ボタンを押す | 毎回のログインで1手間 | 6桁そろったら自動で進む。全角の数字も直す（済み） |
| 2 | 「退会する」が、変更のボタンと同じ大きさで隣 | 押しまちがい | 離して控えめに（済み） |
| 3 | 記録が英語の符丁 | スタッフが読めない | 日本語に（済み） |
| 4 | 保存の失敗が、スタッフに見えない | 気づかずに競りを進める | 赤い警告（済み） |
| 5 | 記録の「前・後」が JSON のまま | 読みにくい | 項目名を日本語にして並べる（未了） |

## Nice-to-Haves
| # | Suggestion | Rationale |
|---|------------|-----------|
| 1 | 管理のタブを URL に載せる | 開き直しても同じタブに戻れる |
| 2 | 参加番号の画面に「この番号が、あなたの番号です」の一言 | 番号の意味がすぐ分かる |

## Interaction Consistency Check
取り消せない操作は、どれも確かめのダイアログを通る。ボタンの主従（濃い色が主）は全画面でそろっている。フッターは、今回、利用者向けの全画面にそろえた。
